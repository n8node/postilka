# Ai агенты

- Центр продукта — не календарь и не отдельный пост, а измеримая задача бизнеса.
- Рабочее название сущности: `mission`; в русском интерфейсе раздел — «Ai агенты», запуск — «агент».
- Основной путь: задача → цель → сведения о продукте и аудитории → наблюдения → проверяемые замыслы → связный ход публикаций → материалы → разрешения → запуск → результат → следующий цикл.
- Календарь остаётся техническим представлением сроков, а не главным способом работы.
- Публикации внутри задачи имеют роли: внимание, проблема, доказательство, выбор, снятие сомнения, действие.

## Два пути и агенты

- Два равноправных пути: человек работает инструментами сам; либо запускает агента.
- Агент — шаблон (системный из админки или пользовательский): промпт, инструменты, лимиты. Задача (`mission`) — конкретный прогон с целью и метрикой. Чат ведёт задачу, не заменяет её.
- Посты агента — те же `posts` с `mission_id` и `origin=agent`. Календарь один; черновики агента можно двигать и править, ход помечается как изменённый вручную.
- Публикация по ходу агента — после явного разрешения. После утверждения отдельные посты всё ещё можно править в композере.
- Конфликты слотов в календаре общие: агент не обходит существующую проверку.
- Встроенный оркестратор — Go + Yandex GPT + существующие `service`. Не встраивать ГигаАгент/OpenClaw как рантайм.
- Later: Public API и MCP, чтобы внешний агент вызывал те же инструменты. Источник истины и публикация остаются в Postilka.

## Первая версия

- Пользователь выбирает задачу, показатель, срок, каналы, частоту и ограничения.
- ИИ анализирует собственные данные проекта, предлагает наблюдения и указывает источник каждого вывода.
- Идея оформляется как проверяемое предположение: изменение, ожидаемый результат, причина, показатель, формат и необходимые материалы.
- ИИ строит связную последовательность и предлагает полный пост, как в композере: вид контента по возможностям канала, текст, фото/видео из файлов или промпт генерации (без автосписания KIE), URL-кнопки только если формат и все выбранные каналы умеют inline-кнопки.
- Новые варианты создаются как черновики. Публикация и изменение утверждённого хода требуют явного разрешения.
- Анализ конкурентов и самостоятельное перестроение хода — после первой версии; использовать только официально и публично доступные данные, не копировать содержание.

## Границы ИИ

- Yandex GPT: уточнение задачи, разбор текста и комментариев, замыслы, последовательность, тексты, сценарии, объяснение результатов.
- KIE.ai: изображения и позднее видео с показом стоимости до дорогого вызова.
- Обычный код: подключённые каналы, ограничения площадок, расписание, публикация, повторы, квоты, платежи и расчёт показателей.
- ИИ не объявляет причинность по одному результату. Разделять: наблюдение, предположение, подтверждённая закономерность, недостаточно данных.

## Измерение результата

- До запуска показывать уровень измеримости: автоматически, частично или вручную.
- Получать доступные показатели публикаций через официальные API площадок.
- Для переходов использовать собственные короткие ссылки на основном домене: `https://postilka.ru/go/{code}` — записать событие и быстро перенаправить на заранее сохранённый адрес.
- Создавать отдельную ссылку для каждой задачи, публикации, канала и варианта; автоматически добавлять UTM-метки.
- Показывать все и примерные уникальные переходы; фильтровать предпросмотры, роботов и аномальные повторы.
- Не создавать открытый перенаправитель: непрозрачный код должен вести только на заранее сохранённый и проверенный адрес.
- Для заявок и покупок позже принимать обезличенные события с сайта, CRM или магазина; не считать переход продажей.
- Минимизировать персональные данные: не хранить полный IP без необходимости, не применять долговременный отпечаток, учитывать 152-ФЗ и согласие.
- Итог задачи обязан отвечать: достигнута ли исходная цель, что сработало, насколько надёжен вывод и что проверить дальше.
